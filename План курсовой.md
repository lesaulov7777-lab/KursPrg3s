## 1. Что требует методичка (выжимка)

### Состав работы
- Пояснительная записка (ПЗ) **20–40 страниц** + программа (ПО).
- Сдаётся: распечатанный отчёт в скоросшивателе + электронный носитель (отчёт, исходники, файлы/библиотеки).
- На защите: демонстрация ПО и **построчное объяснение кода** по требованию преподавателя.
- Оценивают по отзыву: качество кода, полнота выполнения задания, **качество и наглядность графического интерфейса**, качество отчёта (введение/заключение/содержание, проектирование, описание ПО, источники).

### Требования к программе
- Язык: **C, C++, C# или Java**, разработка в IDE. Методичка отдельно упоминает C# и Windows-приложения.
- Суть задания: «реализация базы данных средствами языка высокого уровня» — данные хранятся в файле.
- **Обязательные режимы:**
  1. ввод данных с клавиатуры и создание файла на диске;
  2. чтение и вывод содержимого бинарного файла на экран;
  3. корректировка бинарного файла (удаление, добавление, изменение отдельных полей) **без вспомогательного массива**;
  4. поиск и обработка данных по ключу **без вспомогательного массива** (вспомогательный файл можно);
  5. создание **второго файла** на основе исходного;
  6. чтение и вывод второго файла;
  7. сортировка и фильтрация по параметрам.
- **Обязательно:** контейнеры; обработка исключений; **бинарный режим файлов**; **хэш-функция при идентификации пользователя**; **многофайловый проект**.
- Модульная структура (подпрограммы), защита от ошибок ввода, понятный интерфейс (заставка, меню, понятный ввод).
- Методология: нисходящее проектирование, модульное и структурное программирование.
- Комментарии в листинге обязательны: заголовки подпрограмм, обозначения переменных, заголовки логических фрагментов.

### Структура ПЗ (по разделу 3 и образцу из приложения Ж)
1. Титульный лист (образец в приложении Е; номер страницы не ставится)
2. Задание (бланк с календарным планом; номер не ставится, но считается)
3. Содержание (автоматическое; номер не ставится)
4. Введение (с него начинается нумерация страниц): актуальность, состояние вопроса, цель, задачи, ожидаемые результаты
5. **1 Постановка задачи**: 1.1 Характеристика задачи, 1.2 Выходная информация (таблица сообщений V/P/F + структурные единицы), 1.3 Входная информация
6. **2 Алгоритм решения**: 2.1 Назначение и характеристика задачи, 2.2 Используемая информация, 2.3 Результаты решения, 2.4 Алгоритм (укрупнённые схемы по ГОСТ 19.701-90)
7. **3 Руководство пользователя**: 3.1 Введение, 3.2 Назначение и условия применения, 3.3 Подготовка к работе, 3.4 Описание операций, 3.5 Сообщения пользователю, 3.6 Аварийные ситуации
8. **4 Руководство системного программиста**: 4.1 Общие сведения, 4.2 Структура программы (схема иерархии модулей + спецификация каждого модуля), 4.3 Сообщения системному программисту
9. **5 Контрольный пример**: план тестирования и результаты, скриншоты; начинается **с пустой базы** и последовательно показывает все функции
10. Заключение: что сделано, достоинства и недостатки, сравнение с аналогами, перспективы
11. Список использованных источников (ГОСТ 7.1-2003)
12. Приложение А «Текст программы» (листинг, обязательно)

Каждая структурная единица и каждый раздел основной части начинаются с новой страницы.

### Оформление
- A4, Times New Roman 14, интервал 1,5, выравнивание по ширине, абзацный отступ 15 мм.
- Поля: левое, верхнее, нижнее не менее 20 мм, правое не менее 10 мм.
- Номер страницы внизу по центру (Times New Roman 12), без точки.
- Заголовки структурных элементов (ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ…) прописными по центру; разделы «1 Постановка задачи» с абзаца, без точки в конце, без переносов.
- Рисунки: «Рисунок 1.1 – Название» под рисунком по центру; таблицы: «Таблица 1.1 – Название» над таблицей слева; на все рисунки и таблицы обязательны ссылки в тексте.
- Ссылки на источники в квадратных скобках: [3, с. 12].
- Стандарты: ГОСТ 7.32-2001, ГОСТ 7.1-2003, ГОСТ 19.401-78, 19.402-78, 19.502-78, 19.701-90, ГОСТ 24.xxx.

## 2. Что уже решено (из прошлого чата)

- **Язык:** C++, консольная программа, компилятор g++, редактор VS Code.
- **Управляющая компания** — ЖКХ: хранит персональные данные жильцов (ФИО, адреса, паспорта, лицевые счета, долги).
- **Роль пользователя:** пока только администратор (роль аудитора можно добавить позже).
- **Первая сдача — 31 октября** (через 3 дня): нужно показать продуманную тему и работающий скелет.
- **Черновик раздела 1 «Постановка задачи»** уже есть в Claude Docs: https://claude.ai/artifact/S4CS9ishG4M7oVMGVoHvvV

### Основной файл «Объекты аудита» (`objects.dat`, бинарный)
| Поле | Пример |
|---|---|
| Инвентарный номер (ключ) | УК-ПК-001 |
| Тип объекта | рабочее место / ноутбук / сервер / сетевое оборудование |
| Отдел | бухгалтерия, абонентский отдел, паспортный стол, диспетчерская |
| Ответственный сотрудник | Иванова А. С. |
| Операционная система | Windows 10 |
| Антивирус установлен | да / нет |
| Дата обновления антивирусных баз | 20.10.2025 |
| Пароль соответствует политике | да / нет |
| Обрабатываются ПДн жильцов | да / нет |
| Дата проверки | 27.10.2025 |
| Уровень риска | считается автоматически |

### Формула риска (4 проверки, согласовано)
- нет антивируса: +4;
- антивирус есть, но базы старше 7 дней на дату проверки: +2;
- пароль не соответствует политике: +3;
- объект обрабатывает ПДн и есть хотя бы одно нарушение: +2.

Итог: 0–2 низкий, 3–5 средний, 6 и выше высокий.

### Второй файл «Отчёт о несоответствиях» (`report.dat`)
Строится из основного: объекты с риском не ниже порога, который вводит пользователь. В записи: инвентарный номер, отдел, ответственный, список нарушений текстом, уровень риска.

### Как закрываются обязательные требования
| Требование методички | Как реализуем |
|---|---|
| Ввод с клавиатуры, создание файла | пункт меню «Добавить объект», файл создаётся при первом запуске |
| Чтение и вывод бинарного файла | таблица объектов в консоли |
| Корректировка без вспомогательного массива | правка записи на месте через `seekp`; удаление через временный файл (методичка это допускает) |
| Поиск по ключу без массива | последовательное чтение файла по инвентарному номеру |
| Второй файл и его вывод | отчёт о несоответствиях |
| Сортировка и фильтрация | по риску / дате проверки; по отделу / типу / уровню риска |
| Контейнеры | `std::vector` для сортировки и фильтрации |
| Исключения | свои классы ошибок файла и ввода |
| Хэш при входе | `users.dat`: логин, соль, SHA-256 от (соль + пароль) |
| Многофайловый проект | модули `.h/.cpp` (см. ниже) |

### Предварительный состав модулей
- `main.cpp` — запуск, заставка, вход, главное меню;
- `AuditObject.h/.cpp` — структура записи с полями фиксированной длины, расчёт риска;
- `ObjectFile.h/.cpp` — работа с `objects.dat`: создание, чтение, добавление, правка, удаление, поиск;
- `Report.h/.cpp` — формирование и вывод `report.dat`;
- `Auth.h/.cpp` + `sha256.h/.cpp` — пользователи и хэширование;
- `Input.h/.cpp` — безопасный ввод (строки, даты, да/нет, числа);
- `Exceptions.h` — классы исключений;
- `Menu.h/.cpp` — вывод меню и таблиц.
