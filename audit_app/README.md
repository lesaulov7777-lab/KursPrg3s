# Программа аудита ИБ управляющей компании — скелет

## Как запустить

1. Открой папку `audit_app` в VS Code (File → Open Folder).
2. Открой терминал (Terminal → New Terminal) и выполни:
   ```
   g++ -std=c++17 -Wall *.cpp -o audit
   ./audit
   ```
   Либо через Makefile: `make` (сборка), `make run` (сборка и запуск), `make test` (автоматическая проверка, 20 проверок), `make clean` (удалить результаты сборки). На Windows запускать `audit.exe`. Можно собрать и через Cmd+Shift+B (Ctrl+Shift+B): задача сборки уже настроена.
3. При первом запуске программа попросит создать администратора (логин и пароль), потом войти.

Файлы `users.dat`, `audit.dat` и `report.dat` появятся рядом с программой. Чтобы начать с чистой базы, удали их.

## Что уже работает
- Заставка и главное меню.
- Вход по логину и паролю. Пароль не хранится: в `users.dat` лежат соль и хэш SHA-256(соль + пароль). Даётся 3 попытки, пароль при вводе не отображается.
- Добавление объекта аудита с проверкой ввода: уникальность инвентарного номера, корректность дат, да/нет, выбор из списка.
- Автоматический расчёт риска по 4 проверкам.
- Просмотр всех объектов таблицей (чтение бинарного файла).
- Поиск по инвентарному номеру прямо в файле, без массива, с выводом карточки и списка нарушений.

- **Изменение объекта** (пункт 4): запись правится на месте, через `seekp` и перезапись, без вспомогательного массива. Можно поменять любое поле, риск пересчитывается сам; есть выход без сохранения.
- **Удаление объекта** (пункт 5): с подтверждением. Записи, кроме удаляемой, переписываются во временный файл, который потом заменяет исходный (методичка это допускает).
- При запуске проверяется целостность `users.dat` и `audit.dat`: обрезанный файл не затирается, программа сообщает о повреждении.

- **Отчёт о несоответствиях** (пункт 6): создаётся второй бинарный файл `report.dat`. Основной файл читается по одной записи, в отчёт попадают объекты с риском не ниже выбранного порога (от 1, от 3 или от 6 баллов). Для каждого записываются номер, отдел, ответственный, нарушения текстом и риск.
- **Просмотр отчёта** (пункт 7): вывод `report.dat` на экран. Если отчёт не сформирован или повреждён, программа сообщает об этом.

- **Сортировка и фильтрация** (пункт 8): сначала выбирается фильтр (без фильтра, по отделу, по типу объекта, по уровню риска), потом сортировка (без, по уровню риска, по дате проверки, по инвентарному номеру) и порядок (по возрастанию или убыванию). Результат выводится таблицей, файл не изменяется. Работает на `std::vector`, фильтр через `std::copy_if`, сортировка через `std::stable_sort`.

Все обязательные режимы методички реализованы.

## Модули (многофайловый проект)
| Файл | Назначение |
|---|---|
| `main.cpp` | запуск, вход в систему, обработка главного меню |
| `Menu.h/.cpp` | заставка, меню, таблица и карточка объекта, форма ввода |
| `AuditObject.h/.cpp` | структура записи, справочники, расчёт риска, перечень нарушений |
| `ObjectFile.h/.cpp` | бинарный файл объектов: создание, добавление, чтение, поиск, изменение, удаление, проверка целостности |
| `Auth.h/.cpp` | файл пользователей, регистрация, проверка пароля по хэшу |
| `Sha256.h/.cpp` | хэш-функция SHA-256 |
| `Input.h/.cpp` | защищённый ввод: строки, числа, даты, да/нет, пароль |
| `Query.h/.cpp` | фильтрация и сортировка списка объектов (контейнер `std::vector`, алгоритмы STL) |
| `Report.h/.cpp` | второй бинарный файл: формирование отчёта о несоответствиях, чтение |
| `Date.h/.cpp` | дата: проверка, разбор, разница в днях |
| `Exceptions.h` | классы исключений FileError, InputError |

## Схема вызовов модулей
```
                        main
          ┌──────────────┼──────────────┐
         Auth           Menu        ObjectFile
       ┌──┴──┐       ┌───┼─────┐          │
    Sha256 Input   Input AuditObject  AuditObject
                         ObjectFile       │
                                         Date
```
Все модули при ошибках бросают исключения из `Exceptions.h`; их перехватывают в `main`.

## Формула риска
| Нарушение | Баллы |
|---|---|
| нет антивируса | +4 |
| антивирусные базы старше 7 дней на дату проверки | +2 |
| пароль не соответствует политике | +3 |
| на объекте обрабатываются ПДн и есть хотя бы одно нарушение | +2 |

Уровень: 0–2 низкий, 3–5 средний, 6 и больше высокий.

## Как требования методички закрываются уже сейчас
- **Бинарный режим:** оба файла открываются с `std::ios::binary`, запись пишется целиком через `write`/`read`.
- **Контейнеры:** `std::vector<AuditObject>` для вывода таблицы, фильтрации и сортировки.
- **Исключения:** `FileError` для ошибок файла (программа возвращается в меню), `InputError` для прерванного ввода.
- **Хэш при входе:** SHA-256 с солью.
- **Многофайловый проект:** 11 модулей.
- **Поиск по ключу без массива:** `ObjectFile::findByInv` читает файл по одной записи.
- **Корректировка без массива:** `ObjectFile::update` перезаписывает запись на месте (`seekp`), `ObjectFile::remove` удаляет запись через временный файл.

## Сценарий показа преподавателю (2–3 минуты)
1. Удалить `.dat`, запустить программу: показать заставку и создание администратора.
2. Один раз ввести неверный пароль, потом верный.
3. Пункт 2: база пуста.
4. Пункт 1: добавить `УК-ПК-001` (бухгалтерия, антивирус есть, базы обновлены 10.10, проверка 27.10, пароль плохой, ПДн да). Риск 7, высокий.
5. Пункт 1: добавить сервер без нарушений, риск 0. Попробовать ввести тот же номер или дату 31.02, чтобы показать защиту ввода.
6. Пункт 2: таблица из двух объектов.
7. Пункт 3: найти `УК-ПК-001`, показать карточку с нарушениями.
8. Пункт 4: изменить объект (например, поставить антивирус и исправить пароль), показать, что риск пересчитался. Пункт 5: удалить объект с подтверждением.
9. Пункт 6, порог «от 1 балла», потом пункт 7: показать отчёт с нарушениями. Пункт 6 с порогом «от 6 баллов»: в отчёте остался только объект с высоким риском.
10. Пункт 8: например, фильтр по отделу «Бухгалтерия» и сортировка по уровню риска по убыванию.
11. Открыть `users.dat` в редакторе: пароля в открытом виде нет, только соль и хэш.
